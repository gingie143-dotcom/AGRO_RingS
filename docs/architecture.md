# Архитектура

Это новая реализация по исходному ТЗ. Старый 30-ГБ проект не переносился и не анализировался.

## Границы сервисов

- `frontend`: React + TypeScript; nginx отдаёт статику и проксирует только `/api/`.
- `backend`: FastAPI, SQLAlchemy, Argon2, JWT в HttpOnly cookie, CSRF, CRUD, импорт, история, журнал действий. Не обрабатывает RTP.
- `worker`: единственный диспетчер под PostgreSQL advisory lock. Сначала сохраняет Call, затем передаёт неизменяемый call ID gateway. Не повторяет неопределённый сетевой запрос на набор.
- `voice-gateway`: отдельный FastAPI процесс, идемпотентное принятие сессий в Redis, симулятор; экспериментальная ветка ARI → RTP/PCMU → Realtime.
- `asterisk`: опциональный профиль telephony. SIP-транк, ARI внутри сети Compose, RTP. Исходники Asterisk 22.11.0 проверяются по опубликованному SHA256 при сборке.
- `postgres`: единственный источник истины для CRM и очереди. Данные в named volume.
- `redis`: ограничитель входа и маркеры принятых голосовых сессий; AOF включён. Не заменяет PostgreSQL.
- `maintenance`: ежедневный encrypted pg_dump, задания из UI, удаление старых завершённых звонков.

## Почему очередь в PostgreSQL

Выбор контакта, ограничения и создание звонка должны быть одной транзакцией. Отдельный брокер заданий на этой стадии создаёт ещё один источник состояния. Redis используется там, где не требуется хранить CRM-истину. Для масштабирования нужны outbox/inbox и отдельная приёмка распределённой блокировки; текущий worker намеренно один.

## Состояния

Campaign: draft → running ↔ paused → stopped; running → completed.
Call: queued → ringing → answered → completed/failed/transferred. Cancellation is terminal.
CampaignContact: queued → calling → completed/failed; busy/no_answer допускают ограниченный повтор с паузой, dispatch_uncertain не повторяется автоматически.

Время хранится как UTC; расписание кампании интерпретируется в её IANA timezone.
Пауза/остановка кампании запрещает новые задания; уже принятый звонок завершается отдельно.

## Ограничения текущей реализации

- Только один процесс gateway; лимит в процессе + Redis call ID. Горизонтальное масштабирование gateway пока не поддерживается.
- Реальные кампании заблокированы программно; разрешён отдельный администраторский тест на единственный заданный номер.
- Barge-in очищает локальную очередь, отбрасывает позднее аудио старого item и отправляет truncate. Уже переданный в телефонную сеть звук нельзя отозвать. Его фактическая задержка должна быть измерена.
- RTP парсер проверяет формат и отправителя, но полноценный jitter buffer и пересортировка пакетов не реализованы.
- Нет обещаний достоверного распознавания эмоций, интереса или намерений. AI-оценки требуют отдельной валидации.
- UI показывает загруженную первую страницу; серверные limit/offset и поиск есть для базовых справочников.
- Учетные записи общие для одной организации. Мультитенантность отсутствует.
