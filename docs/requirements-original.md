# Техническое задание для Codex

Ты — ведущий архитектор ПО и senior full-stack разработчик. Твоя задача — создать локально на моём компьютере полноценную модульную платформу AI-обзвона с разными адаптивными агентами без голоса робота, через SIP-телефонию.

Это НЕ учебный пример и НЕ одноразовый demo-проект. Строй систему так, чтобы после тестирования её можно было перенести на VPS и масштабировать.

## 1. Мой компьютер

ОС:

- GPU: NVIDIA RTX 5060
- RAM: 32 ГБ
- SSD: 1 ТБ

Разработка и запуск:

- Docker Desktop
- Docker Compose
- все сервисы должны запускаться локально
- конфигурация через `.env`
- секреты и API-ключи никогда не помещать непосредственно в исходный код

## 2. Главная задача

Создать AI Voice Agent для исходящих звонков через SIP.

Система должна:

1. Загружать базу контактов.
2. Создавать кампании обзвона.
3. Совершать исходящий SIP-звонок.
4. Соединять звонок с AI-агентом.
5. Получать голос человека в реальном времени.
6. Распознавать речь.
7. Понимать смысл ответа.
8. Формировать следующий ответ с учётом контекста.
9. Озвучивать ответ естественным голосом.
10. Поддерживать перебивание AI человеком.
11. Определять, хочет ли человек продолжать разговор.
12. Анализировать эмоциональный тон и заинтересованность осторожно, без выдачи предположений за факты.
13. После звонка формировать структурированный результат.
14. Сохранять всю историю отдельно для каждого контакта.
15. Различать компании, контакты и отдельные звонки.
16. Позволять назначать следующий звонок.
17. Передавать заинтересованного человека живому оператору.
18. Вести статистику кампаний.

Телефония также должна быть отделена от бизнес-логики.

## 4. Реальный голосовой диалог

AI не должен просто читать заранее записанный скрипт.

Он должен работать как собеседник.

Агент должен:

- понимать смысл сказанного;
- учитывать предыдущие реплики;
- реагировать на неожиданные ответы;
- задавать уточняющие вопросы;
- перефразировать непонятный вопрос;
- учитывать темп разговора;
- не перебивать человека;
- прекращать собственную реплику при перебивании;
- поддерживать естественные паузы;
- не повторять один и тот же вопрос;
- уметь завершить разговор;
- уметь передать разговор оператору.

При этом нельзя заявлять, что система достоверно определяет мысли, личность или эмоции человека. Любой анализ настроения хранить как вероятностную оценку с соответствующей пометкой.

## 5. Профиль контакта

Для каждого контакта создать отдельную карточку.

Хранить:

- имя;
- телефон;
- компания;
- должность;
- дополнительные поля;
- историю всех звонков;
- дату последнего контакта;
- дату следующего контакта;
- результаты предыдущих разговоров;
- интересы/потребности, выявленные из разговоров;
- возражения;
- предпочтительный следующий шаг;
- статус контакта.

История должна быть привязана к конкретному контакту и компании.

Один контакт может иметь много звонков.

Каждый звонок должен иметь собственную запись.

## 6. Запись каждого звонка

Предусмотреть настройку срока хранения.

## 7. Анализ после разговора

После каждого звонка AI должен сформировать JSON-результат примерно такого типа:

{
"call\_status": "...",
"conversation\_summary": "...",
"customer\_intent": "...",
"interest\_level": 0,
"objections": [],
"important\_points": [],
"next\_action": "...",
"callback\_required": false,
"callback\_datetime": null,
"transfer\_to\_human": false,
"conversation\_quality": 0
}

Не использовать эти поля как медицинскую, психологическую или иную достоверную диагностику человека.

## 16. Резервное копирование

- ежедневный backup;
- ручной backup из панели;
- хранение нескольких последних копий;
- возможность восстановления;
- проверка успешности backup;
- логирование ошибок.
