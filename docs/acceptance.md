# Приёмка на Windows 11 + Docker Desktop

Не отмечать этап пройденным без фактических результатов. Симуляция не подтверждает SIP или AI.

## 1. Окружение и контейнеры

1. Открыть Docker Desktop, включить Linux containers/WSL2.
2. Выполнить `./scripts/preflight.ps1`.
3. Выполнить `./scripts/start.ps1`; затем `docker compose ps`.
4. Открыть http://localhost:3000; логин из `.env`.
5. Проверить `docker compose exec backend python -c "import urllib.request; print(urllib.request.urlopen('http://localhost:8000/ready').status)"`.
6. Запустить `./scripts/test.ps1`.

## 2. Данные и симуляция

1. Создать сценарий, агента и контакт с тестовым основанием для звонка.
2. Создать кампанию с текущим разрешённым временным окном. По умолчанию будни 09–18.
3. Добавить контакт в кампанию, запустить; открыть «Звонки» после обновления.
4. Проверить три искусственные реплики и `simulation=true` в результате.
5. Создать контакт, выполнить `docker compose down`, снова `docker compose up -d`; контакт должен сохраниться. Никогда не добавлять `-v` при обычном обновлении.
6. Проверить отказ от обзвона, повторный импорт того же номера, запрет его включения в очередь.
7. Пауза и остановка не должны порождать новые звонки. После неопределённого сетевого сбоя автоматического повторного набора нет.

## 3. Backup/restore

1. Создать тестовую компанию с уникальным названием.
2. Сделать backup из настроек или `./scripts/backup.ps1`.
3. Восстановить `./scripts/restore.ps1 -File <имя.dump.enc> -Database restore_acceptance`.
4. Проверить таблицы и контрольную компанию в restore_acceptance через psql.
5. Убедиться, что исходная база не изменена. Проверить отдельное безопасное хранение BACKUP_KEY.
6. Проверить поведение при недоступности диска и неверном ключе. Статус должен быть failed, а не completed.

## 4. Одиночный SIP/AI-тест

См. sip.md. Не включать реальные кампании до успешной проверки.

1. Настроить SIP-транк и сеть, дождаться регистрации.
2. Настроить OPENAI_API_KEY, LIVE_TEST_NUMBER и LIVE_CALLS_ENABLED=true только локально.
3. Остановить worker: `docker compose stop worker`.
4. Вызвать POST /api/test-call под администратором, передав contact_id, scenario_id, agent_id. Это реальный платный вызов на разрешённый номер.
5. Проверить минимум три осмысленные реплики и память контекста.
6. Перебить AI; измерить фактическое прекращение старой речи на телефоне.
7. Проверить hangup, invalid key, rate limit, разрыв WebSocket, no answer, недоступность БД.
8. После завершения проверить отсутствие оставшихся ARI-каналов, мостов и AI-сессий.
9. Записать версии, provider/model, аудиоформат, задержки и результаты; реальные кампании до этого не разблокировать.

## 5. Не реализованные критерии полного ТЗ

Приёмка post-call AI JSON-анализа на реальном API, перевод живому оператору, голосовые tool calls для opt-out/завершения, полный набор настроек/редактирования в UI, автоматические callback-звонки, запись и воспроизведение аудио, сквозные метрики latency, нагрузочные/failure-тесты и clean-machine прогон.
